# Astro Starlight Demo (Option 6)

Local demo of **Option 6 — Astro (Starlight)** from `DESIGN.md` /
`ACTION_PLAN.md` §2.6. Serves the shared sample content (design doc, SOPs,
runbook) with Starlight features showcased.

Astro 7.1.6, Starlight 0.41.11, React 19 (islands), MDX.

## Setup

```bash
npm install
```

## Dev server (port 4106)

```bash
npm run dev          # astro dev --port 4106
```

## Build (static, SSR at build time)

```bash
npm run build        # output in dist/
npm run preview      # serve the build on port 4106
```

## Content layout

- `src/content/docs/design/architecture/` — design doc (with React island); a
  directory with `index.mdx` so the POC subpage can nest under it in the sidebar
- `src/content/docs/design/architecture/poc-subpage.mdx` — POC subpage nested
  under Architecture in the autogenerated sidebar
- `src/content/docs/sops/` — deploy-release, rotate-credentials
- `src/content/docs/runbooks/` — high-error-rate
- `src/content/docs/images/` — images, referenced relatively (`../images/...`) so they go through Astro's asset pipeline
- `src/content.config.ts` — typed content collection (Starlight docs schema + `severity` enum)
- `src/components/OrderStateStepper.tsx` — interactive React island
- `astro.config.mjs` — Starlight (sidebar autogroups), `astro-mermaid`, MDX, React, `base: '/github-pages-docs/astro/'`

## Gotchas / notes

- **`astro-mermaid` vs `@astrojs/mermaid`:** the package on the npm
  registry that works with current Astro is `astro-mermaid` (the
  `@astrojs/mermaid` name is not published in a compatible form). It must be
  registered **before** `starlight()` so its markdown plugin runs first.
- **Sätteri MDX compiler:** Astro 7 uses the Sätteri MDX processor, which
  needs `features: { rawHtml: true }` to compile the raw HTML that
  `astro-mermaid` emits for ```mermaid blocks in `.mdx` files.
- **Dark default:** Starlight ≥ 0.39 always starts dark then follows OS
  preference; the inline seed script keeps "dark on by default" for first
  visits.
- Image paths: images live in the source tree (`src/content/docs/images/`) and are
  referenced relatively (`../images/...`). Astro bundles them through its asset
  pipeline, which prepends `base` automatically. (Public-folder references like
  `/images/...` are passed through verbatim and would break under a non-root
  base — see the base-path gotcha below.)
- **Base path (`/github-pages-docs/astro/`):** the site is built with
  `base: '/github-pages-docs/astro/'` so it works under the mock server's
  subpath (`server/server.mjs`) and on GitHub Pages, where this project lives
  in the `github-pages-docs/` subfolder of the `frankyz-dev.github.io` user
  site. Starlight applies `base`
  to its own generated links (sidebar, nav) and to asset-pipeline images, but
  **not** to links written in content/frontmatter (known limitation,
  withastro/starlight#3660). So content links stay relative: the splash page's
  hero actions use `link: design/architecture` (relative to the index page), and
  markdown images use source-tree relative paths.
- **Sidebar nesting (POC):** Starlight sidebar entries are either links or
  groups — a link item cannot carry `items` (its schema is a strict object),
  and `link` is for external/non-docs URLs (internal pages use `slug`). To nest
  the POC Subpage under Architecture, the design doc lives in a directory
  (`design/architecture/index.mdx`) with the subpage beside it; autogenerate
  renders the directory as a collapsible group (label = directory name) with
  the index page as its first link. A directory always becomes a group — the
  index page cannot be the parent link itself.
